## OPEN notes and production blockers

- **Cron per tenant:** no tenant discovery or fan-out exists. For the first single-tenant beta, the smallest config-only follow-up is changing the cron path to `/api/cron/due-events?tenantId=<actual-tenant-uuid>` after bootstrap. Do not commit guessed IDs. For more tenants, static entries require one deployment change per tenant and depend on provider job limits. Verify those limits in the console. The smallest scalable code follow-up is a secret-authenticated dispatcher with a reviewed active-tenant enumeration, bounded batches and one explicitly tenant-scoped processor call per tenant. Do not add an unscoped query to the current route without reviewing that boundary. Decide cadence against the due-time requirements; hourly here is provisional, not an agreed reminder SLA.
- **CSP:** omitted. Next streamed inline scripts and Astryx runtime/style requirements have not been inventoried for a nonce/hash policy. Follow up with report-only measurement across both locales, auth, streamed pages, styles and PWA before enforcing a policy. No CSP compatibility claim is made.
- **Hosted migration grant:** 0000's unconditional role grant can block hosted migration. Apply only the security model's reviewed H0 fix before first deployment if the permission preflight fails. No migration was changed in this batch.
- **Storage:** no checked-in bucket-policy setup; remote upload-completion stamping remains an unproved flow. Both are gates for the payment-proof/form acceptance path. Branding asset uploads are not implemented. Private buckets alone do not defeat an existing broad `storage.objects` policy.
- **Storage, signed upload limits (pre-review S2, accepted until hosted):** a hosted signed upload URL binds neither the declared size nor the MIME type, so the bucket settings in step 6 (8 MiB, MIME allowlist) are the only server-side enforcement. A bucket allowlist is shared by every purpose, so a progress photo can still arrive as a PDF. Before real clients upload, prove the limits with a live oversized and a wrong-type upload, and decide whether to add a post-upload check that reads the stored object's size and type before the row becomes visible.
- **Hosting root:** workspace-root Next adapter/tracing must be proved on staging. Config is locally valid JSON, not a verified hosted deployment.
- **Auth:** invite/recovery and confirmation delivery must pass on hosted Auth. Closing signup is a product decision with consequences for current invitation signup. Resend application settings do not configure Supabase Auth delivery.
- **Release evidence:** no hosted migration, production build, live email/push, account configuration or restore has been performed by this batch. Task 12 gates, counsel approval, budget approval, and a signed restore drill remain mandatory. See OPEN_DECISIONS 7-10 for form-state and UI gaps; they must be assessed in the acceptance flow rather than treated as fixed by deployment configuration.
